# 按需便签生命周期

human_cli 是 AI 调用的人机协作工具。它不提供主界面、待机窗口、历史记录窗口或托盘入口。AI 创建请求时显示任务便签；用户完成或 AI 取消后，对应窗口立即隐藏并销毁。回复先持久化到本机缓存，不保留完成结果页。

- 多个请求可以并行。结束一张便签不会影响其他便签。
- 未完成请求没有用户操作期限。AI 连接断开不取消任务；用户仍可以完成并留下缓存。
- 暂时离开可最小化便签到任务栏，从任务栏恢复。系统关闭窗口操作同样最小化，不替 AI 取消。
- 主题从任务便签内修改，偏好与位置、尺寸仍然持久化。
- 没有未完成请求时，桌面端在正在处理的 HTTP 响应传完后退出。CLI/MCP 下次调用会按需启动它。MCP 适配器连接仍可保持，不要求 Electron 桌面进程常驻。
- 查询 logs/get/result/plugins 本身不会创建窗口；启动恢复时若本来存在未完成请求，则恢复这些任务便签。完成的历史只留在数据、缓存及 AI 接口里。
- 直接启动桌面 EXE 而没有任务时，不显示窗口并自行退出。

`desktop/lifecycle.mjs` 根据未完成请求数和活动 HTTP 响应数管理退出。空启动有 5 秒启动衔接窗口，空闲响应结束后留 250ms 用于连续调用衔接；这两项只影响无任务进程回收，不限制用户任务或正在回传的响应。健康检查不延长空启动期限。

退出与新调用发生竞争时，GET 可重试；创建请求的传输重试复用同一个幂等键，防止第一次创建成功但响应丢失时生成重复便签。查询可以从缓存重启恢复，不需要 AI 发送确认回执，也不把进程退出当作 AI 收到结果的证明。

验证入口：

```powershell
npm test
npm run test:lifecycle
npm run test:native
npm run test:config-ui
```

生命周期原生验证使用真实 Electron 进程和 CLI：无窗口启动、用户输入期间保持等待、并行任务独立结束、完成后窗口销毁、最后一个任务结束后进程退出、重启无历史窗口、通过日志恢复缓存及只读进程回收。测试控制通道仅位于 tests/，不随产品打包。
