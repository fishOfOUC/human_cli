# 已知问题

## 回复框输入时偶发丢失字母

- 记录时间：2026-10-29。
- 来源：用户在界面验收便签中的反馈，请求 ID 为 `28b45b5c-aefc-48fa-b38d-facaa611ff50`。
- 现象：回复框输入时偶尔丢失字母。
- 状态：2026-10-30 已修复已确认的输入框重建及组合输入中断问题；搜狗、青简的实际候选栏表现仍待用户验收。
- 原因：输入停顿 200 毫秒后自动保存草稿，状态广播触发整张便签重建，销毁 textarea 和 composer。恢复文字与光标无法恢复原来的组合输入会话；其他便签的更新也会触发重建。
- 修复：局部更新便签并按 blockId 保留文字输入框；组合期间暂停草稿保存、延迟状态渲染；选词结束后保存最终文字。Escape、Ctrl+Enter 避开组合输入，状态通知按请求定向发送，置顶状态仅在变化时设置。
- 验证：`npm run test:input` 使用隐藏的隔离 Electron 窗口和 Chromium 原生组合输入接口，覆盖输入间停顿、组合提交/取消、快捷键、外部任务与主题更新、其他便签更新、附件异步完成及多段回复。它不等同于搜狗、青简实机验收。
- 处理历史：最初按用户要求“记下这个问题，先不修”仅作记录；2026-10-30 用户授权修复后实施上述修改。
- 后续澄清：用户此次反馈的空回复是未输入内容直接确认，不能作为丢字的复现证据。空提交现在通过 submission.type=confirmation_only 明确标注完成确认；该标记只说明提交动作及提交内容为空，不表示验收通过，也不判断是否存在输入丢失。
